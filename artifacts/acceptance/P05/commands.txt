Round 1 audit (orchestrator, Opus 5.5)
======================================
Read every new and changed file. Reverted two generated files outside the
allowlist (next-env.d.ts, P00 playwright-report/index.html). Findings fixed by
the orchestrator:
1. Data loss: two completions of one ticket. The second failed at
   media_complete and its cleanup deleted the first one's public derivatives
   and private original. Fix (migration): media_claim(actor, ticket) claims a
   ticket once at the start of completion; media_ticket (PUT) refuses a claimed
   ticket; media_complete requires the claim. No cleanup can touch another
   request's result, and a failed ticket is not retried (the browser takes a
   new ticket).
2. Check-then-swap: derivatives were verified from one read and promoted from
   a second read, so a parallel PUT could swap bytes between them. Fixed twice
   over: the claim blocks PUTs, and each derivative is now verified and
   promoted from the same buffer.
3. md5: R2 checksums.md5 is an ArrayBuffer; the route passed it raw, so rows
   held '{}'. Now hex, and the column checks ^[0-9a-f]{32}$.
4. The original's head read now asks for min(size, 1 MiB), not always 1 MiB.
5. The worker's "stays within the 10 ms CPU ceiling" claim was unmeasured;
   both ponytail comments now say P10 measures it.
6. /media route reads MEDIA_PUBLIC_ORIGIN through optionalEnv, like the rest.
Tests added: claim is one-shot, claimed tickets refuse parts, cross-actor and
expired claims, unclaimed completion refused, media_claim not callable by API
roles; e2e second completion 410 with the first result still served, PUT after
use 410, stored md5 equals the original's md5. The HTML-spoof e2e no longer
retries on the same ticket (by design); private deletion after a failed
completion is proven by code reading, not over HTTP.
