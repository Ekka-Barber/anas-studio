## 3. I40: the build check against demo rows

**Legitimate «تجريبي» in the source.** Checked first, with `grep -rn "تجريبي" src content DESIGN.md public`. It appears only in admin code:
- `src/admin/tables/products.ts:48`, the list badge;
- `src/admin/tables/index.ts:57`, a comment;
- `src/app/(admin)/admin/store/StoreHome.tsx:66`, the notice «بيانات المتجر الحالية تجريبية…».

Nothing in `content/`, `DESIGN.md` or `public/` contains it, and no public page renders it. In the export, the admin strings live only in JavaScript chunks (`0ucw7aqw279lv.js`, `2k_4a0wjeaxak.js`, `2cm6sn7bbwj29.js`). Admin HTML shells carry none. So the guard reads only HTML visible text, never the JavaScript.

**The demo flag.** The build output does not show it. `src/lib/store.ts` loads `demo` into `StoreProduct`, but no component renders it or passes it on. A grep for `"demo":true` over `out/**/*.html` and `*.txt` finds nothing. Recognition therefore rests on «تجريبي» in visible text.

**The decision** (`scripts/lib/demo-guard.mjs`, `checkDemoContent(files)`):
- **Finding the origin.**
  - An origin counts only when an `http(s)://host[:port]` is followed by `/rest/v1`, `/functions/v1`, `/storage/v1` or `/auth/v1`. It is read from every `.html` and `.js` file in `out/`.
  - The shell environment is never read.
  - A bare URL is not accepted, because supabase-js ships its own `"http://localhost:9999"` default (in `3c2tqa0r34nsn.js`).
- **Loopback.** The host must be `localhost`, `127.0.0.1` or `[::1]`, or end in `.localhost`. The build counts as local only if every origin found is loopback. A mixed set counts as hosted.
- **Demo content.** A `.html` file whose text, after removing `<script>`, `<style>`, comments and tags, contains «تجريبي».
- **Outcomes.**
  - No origin found: the check fails with "cannot find the Supabase origin (NEXT_PUBLIC_SUPABASE_URL) in the built JavaScript or HTML, so a local build cannot be told from a production one (PLANS/ISSUES.md I40)".
  - Hosted with demo content: the check fails, naming the origin, every page and I40.
  - Loopback with demo content: the check passes and prints one line.
  - No demo content: the check passes and prints the origin.
  - Messages carry origins and page paths only, never a key.

**Proof against the current local `out/`**, built 2026-09-28 23:13. `pnpm check:export` exited 0:

## Risks

- **Where the guard runs.** It protects production only where `pnpm check:export` runs after the production build.
  - CI builds against the local stack, so it always takes the loopback path.
  - The Cloudflare Pages build command is a P11 item. It must run `pnpm build && pnpm check:export`, or the deploy must gate on it, for I40 to block a real deploy.
- **D37 and a hosted preview.** D37 lets the owner decide at P11 whether demo rows reach the hosted project. A hosted build that shows them will fail this check by design. No override was added.
- **Text-based detection.**
  - If Anas edits a demo row until none of its visible text says «تجريبي» but `demo` stays true, the guard cannot see it.
  - The demo coupon, city rates and seller settings are read at runtime by checkout, never baked into HTML.
  - The I40 launch step, "confirm the production database has no demo rows", is still needed.
  - The match is the plain word «تجريبي» (it also matches «تجريبية»), which is ordinary Arabic for "experimental". If Anas's real content ever shows it on a page (for example «مشروع تجريبي» in a journal post), every hosted production build fails, and the message asks to remove demo rows. It fails closed; narrowing the match to the seed's exact markers is a product choice left open.
- **Fail-closed on origin.** Finding the origin relies on the minifier folding the URL into one literal. If a future toolchain stops doing that, the check fails with the clear "cannot find" message; it never falsely passes.
- **What counts as loopback.** Exactly the brief's list. A LAN IP or `host.docker.internal` counts as hosted.
- **Pre-existing, unchanged:**
  - `staff-admin` imports the unpinned `npm:@supabase/supabase-js@2`, which resolved to 2.117.2 today; the other functions pin 2.117.1.
  - The Deno used here is 2.9.6; the edge runtime's own Deno 2 may differ.
- **Pre-existing, noticed, not changed.** In `scripts/check-export.mjs` the `TEXT` pattern ends in `\/_headers$`. On Windows the path has a backslash, so `out/_headers` is not secret-scanned; Linux CI scans it.
