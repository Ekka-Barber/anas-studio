== Incidents and resolutions ==
1. First e2e run: POST /api/jobs/run sent with the REAL Resend key. Cause: the gitignored .env
   defines RESEND_API_KEY and next dev loads .env in addition to .env.local, so sendEmail chose
   the Resend path. Every send was refused by the provider (422, unverified sender) — NO real
   email left, confirmed by last_error HTTP_422 on the affected outbox rows (they are marked
   exhausted in the local database). Fix: scripts/local-env.mjs now writes an empty
   RESEND_API_KEY= into .env.local (higher precedence than .env; empty counts as unset in
   optionalEnv), forcing the Mailpit dev path. Dev server restarted before the passing run.
2. "Bad Turnstile token" e2e: impossible locally — the always-pass test secret accepts any token
   (live evidence above). The test now asserts the over-length-token 422 (schema) instead; the
   400 TURNSTILE mapping is covered by tests/unit/turnstile.test.ts (INVALID_TOKEN,
   ACTION_MISMATCH, HOSTNAME_MISMATCH, UNREACHABLE, TEST_SECRET_IN_PRODUCTION).
3. Dev submissions share the literal `local` IP bucket (5/hour, fixed window), so repeated e2e
   runs inside one clock hour returned 429. The spec now sends a unique cf-connecting-ip per run
   (the route's documented IP source).
4. Integration failures above were all test-side assumptions on the shared disposable local
   database; no product change followed from them.

Incident (reported by the worker, verified by the orchestrator): the first e2e
run called the real Resend API, because `next dev` also loads `.env`, which
holds the owner's RESEND_API_KEY, and the brief chose Resend whenever that key
was set. Resend refused every request (30 rows exhausted with HTTP_422, one

an @example.com test address. So no email was delivered, but the real key was
used about 31 times from a local process. The worker's fix (an empty
RESEND_API_KEY= in the generated .env.local) depended on env file precedence.
Orchestrator fix in code: `emailProvider()` chooses Resend only in a
production build whose SITE_URL is not a loopback host, and Mailpit only
outside production; the outbox uses the same check. Regression tests: a Resend
key is ignored outside production (Mailpit used, api.resend.com never
fetched); a production build with a local or missing SITE_URL (a local Worker
preview) sends nothing.

Other findings fixed by the orchestrator:
- The Resend webhook acknowledged a failed database write with 200, so the
  provider would never redeliver and a bounce or complaint (and its
  suppression) could be lost. Now 503, which the provider retries; the event
  id dedupe makes redelivery safe.
- An unparseable created_at or an event id over 200 characters would have
  failed the insert on every redelivery; created_at is now validated (else
  null) and an oversized svix-id is refused before recording.
Accepted as reported: Turnstile test secrets skip the hostname and action
checks outside production (live siteverify returns hostname example.com and no
action for them), refused outright in production; 409 resource_locked → retry.
