  `RESEND_API_KEY`. No secret appears anywhere outside `.env`, and
  `.env.example` still has zero non-blank assignments.
- Re-measured the Worker independently with `wrangler deploy --dry-run`, which
  is the same bundling path a real upload uses. It confirmed the builder's
  figure: `Total Upload: 25320.88 KiB / gzip: 5607.11 KiB`, reproduced again
  from a clean container build at `gzip: 5607.12 KiB`.

  **Correction, same day.** The audit then compared that figure to a 3 MiB
  Workers Free ceiling and raised I01 as a blocker requiring a paid plan. The
  ceiling was wrong: Cloudflare enforces **64 MiB uncompressed on both plans**
  and explicitly does not enforce a compressed size. The enforced number here is
  24.73 MiB, about 39% of budget. I01 is withdrawn; see it for the root cause.
  The audit verified the measurement twice and the limit zero times, which is
  the specific failure to avoid repeating: a vendor limit that gates a purchase
  or an architecture change is cited from current documentation, never recalled.
- Read the previously failing scheduled-job test. It was strengthened, not
  relaxed: it records the last completion before it starts, requires a newer
  one, and additionally requires the probe row's database write. The root cause
  the builder identified — Payload's `deleteJobOnComplete` defaulting to true,
  making a completed job unobservable — is a real defect in the health endpoint,
  and fixing it was correct.
- Repointed the migration `DATABASE_URL` to the session endpoint (ISSUES R01).
  The builder was right to refuse to edit `.env` and report it instead.
