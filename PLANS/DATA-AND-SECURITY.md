# Data model, authorization and transaction rules

This is an implementation contract for P03–P09. UUID primary keys default to `gen_random_uuid()`; UTC `timestamptz`, `created_at`, `updated_at` apply to mutable entities. Every editable row has integer `version` for compare-and-swap updates. Currency is `SAR`; every money column is a nonnegative integer number of halalas, with checked arithmetic and a configured maximum checkout total. No float totals. SQL functions set `search_path = ''` and qualify every object. Run schema and policy tests against real PostgreSQL, not mocks.

Do not expose rows with missing/unapproved prices. A disabled third plain-paper edition may preserve the three-card visual layout with truthful unavailable copy; no nonexistent SKU is purchasable. The offer explicitly starts with digital and signed paper; ordinary paper is optional owner activation within existing edition management.

## Database authorization matrix

| Entity | Anonymous | Editor | Operations | Owner | Integration |
|---|---|---|---|---|---|
| Published content/settings/policies, public catalog/service fields | SELECT eligible projection | Read | Read | Read | Read only if needed |
| Drafts/revisions/taxonomies/projects/scenes | None | CRUD + publish | None | CRUD + publish | Scheduler functions only |
| Media originals/rights | None | Validated upload/use/archive | Read fulfillment assets only through action | CRUD | Verify/transform/download functions only |
| Customers/orders/items/payments | None | None | Read, fulfillment transitions | Read + owner refunds | Explicit checkout/payment functions |
| Coupons/shipping/prices/stock/services | Published subset only | None | Read | Configure | Reservation functions only |
| Bookings/inbox | Submission routes only | None | Read/update operational fields | All operational fields | Validated submit/due functions |
| Team/security/secrets settings | None | Own membership/security only | Own membership/security only | Invite/role/revoke with MFA | Auth invite API after owner authorization |
| Audit/backups/job detail | None | Own relevant edit history | Relevant fulfillment history | Read, request backup/restore workflow | Append/due status only |

Enable RLS on every application table, including new tables added later. No anonymous insert on forms/orders; only validated server routes call explicitly allowed RPCs. Revoke public EXECUTE on every privileged function. Functions exposed to staff check `auth.uid()`, active DB role and `auth.jwt()->>'aal'` where required; never take actor/role as an untrusted caller parameter. No self-promotion through profile/user_metadata. SQL permission tests exercise REST with anonymous, editor, operations, owner and revoked-user JWTs, not only server UI.

The server integration key is an intentional elevated trust boundary. Revoke its direct DML grants on application tables; grant EXECUTE only to specific integration RPCs. Those functions validate invariants again, perform narrow transactions, append audit and accept no raw SQL/table name. Supabase service role bypasses RLS, so RLS alone does not protect a leaked integration key; least grants, secret isolation, no browser import and key rotation are required. Migration/backup credentials are separate and never present in the web bundle. Verify effective grants in tests; do not assume dashboard defaults match this contract.

## Checkout transaction

1. Browser stores only variant IDs, quantities and cart schema version in localStorage. Never trust its totals; discard malformed/unknown variants. A cart can survive reload, but quote/prices are fetched again. Storage denial still permits session cart. No customer/address data in localStorage.
2. Quote resolves enabled product/variant and owner-set prices, policy/tax setup, city shipping and coupon eligibility. Empty cart, mixed booking plus physical items, unknown/disabled variant, too many lines (>50), quantity outside 1–20 or invalid dedication fails. One booking per order; ordinary physical/digital mixed cart is supported. Sum and discount in integers; no float rounding. Proportionally allocate discount/tax to lines with deterministic remainder so refunds reconcile exactly.
3. Final POST uses an idempotency key; same key+same payload returns same order, same key+different payload returns 409. Lock variant rows in sorted ID order, coupon row and booking reservation. Recheck versions and availability. Reserve all resources and write order/items/policy snapshots/outbox in one transaction or none. Hold default 20 minutes, invoice expiry no later than hold expiry. A paid booking has the same expiry rule.
4. Create the invoice outside the DB transaction with a durable attempt in `creating`. Store its ID and URL, then return it. Never hold SQL locks across network calls. On timeout mark `uncertain`; reconcile using the stored provider reference/idempotency contract, never blindly issue duplicate invoices. If provider creation has no documented idempotency support, do not invent a header: reconcile first or cancel/review the uncertain attempt. A second concurrent request cannot create a second active payable attempt for the order.
5. Redirect/success query parameters are display hints only. Until authoritative verification finishes, show «جارٍ التحقق من الدفع» with a safe refresh. Do not clear the cart or issue downloads on a callback status string.
6. Webhook: verify documented `secret_token` with constant-time comparison and validate `live` matches expected mode. Persist an event ID durably before ACK, then fetch gateway payment and invoice with secret credentials. Check exact invoice/attempt mapping, account/environment, payment status, expected full amount, currency and refund fields. The unique invoice mapping is the order binding; metadata alone is insufficient. Do not assume every webhook has the same payload shape. Invoices' callback endpoint is only a prompt to reconcile; use the same fetch checks, not an invented HMAC scheme.
7. `apply_verified_payment` locks order, attempt and reservations. The first fully verified paid result commits stock/coupon/booking, grants digital entitlement if asset ready, and queues one receipt; duplicate/reordered events do not repeat any of these. `authorized`, `verified` or merely `initiated` is not paid. Record partial/over/under currency or amount mismatch for review; never fulfill it.
8. If payment arrives after a reservation expired, reacquire stock/slot transactionally. If unavailable, set `paid_needs_resolution`, do not oversell or promise the appointment, and notify owner for refund/rebooking. The money remains recognized; it is never relabelled failed because fulfillment failed. Free an expired held slot before a new reservation; exclusion constraint prevents two active overlaps.
9. Reconcile pending/uncertain attempts every minute in bounded batches, backing off after repeated provider errors; keep manual retry on owner order view. Durable events/outbox survive Worker restarts. Webhook retries are finite, so webhook-only completion is not adequate.

## Refund, return and delivery

Owner MFA confirms amount/reason on the order. Create a refund intent under lock; reserve refundable balance including pending/uncertain intents so simultaneous refunds cannot exceed payment. Call gateway outside transaction. On response timeout remain uncertain and fetch authoritative payment/refund state before retry. Only confirmed gateway state marks financial refund succeeded. Duplicate events dedupe on provider ID and internal intent. Partial refunds allocate to order items; revoke only affected digital entitlement/booking, preserve unaffected items. Full refund revokes all entitlements. Do not automatically restock shipped/returned goods before owner marks them received and sellable.

Digital receipt links lead to scoped tokens, never the raw R2 key. Order-access links expire after 7 days and may be reissued after a generic email recovery request; a download token expires after 15 minutes, at most 3 issuances, with a 60-second object signature. Token hashes use a server pepper; rotate by version. A leaked already-issued signed object URL remains usable until its short expiry; do not promise instantaneous DRM. Use `Referrer-Policy: no-referrer`, attachment disposition with a safe UTF-8 filename and `X-Content-Type-Options: nosniff`. Refund/revocation prevents new links.

Physical orders require supported shipping address and phone; digital-only orders do not request address. Operations marks preparing, shipped and delivered; tracking and customer emails use dedupe keys. Signed edition supports dedication text and a fulfillment checklist. Returns start as customer requests and have a staff trail. Record all financial and stock changes in audit, not only the last status.

## Upload and document security

Editor asks for a purpose-specific ticket with a randomized server-owned object key. Permit JPEG/PNG/WebP/AVIF up to 15 MiB and 40 megapixels, PDF up to 100 MiB; reject SVG/HTML and archives in user uploads. Existing reviewed SVG signature is a bundled trusted asset, not a reason to accept arbitrary SVG. Direct upload targets private quarantine, expires after 5 minutes and is scoped to exact key and declared limits. Completion verifies object length, actual signature/MIME and decoded dimensions; a client `Content-Type` is not proof. No successful media row until validation completes.

Images are decoded/re-encoded by the transformation service; strip metadata, generate bounded width presets 360/720/1200/1800, store dimensions/format, retain original privately. Crop selection is server-validated within actual dimensions; never arbitrary remote URL fetch. Rights/alt text required before public use. PDFs stay private, have signature/size/page metadata checked, never execute embedded JavaScript; public preview PDF is an independently exported approved excerpt. Treat parser output as untrusted; use patched PDF.js with `isEvalSupported:false`, no auto-open actions or arbitrary PDF attachment links. Never copy the manuscript into `public/` or a static deploy artifact.

## Preview, sessions, conflicts and data loss

Draft preview uses an authenticated staff route/session and noindex/no-store. No bearer preview URL shared with anonymous visitors by default. Staff authentication uses PKCE/code exchange, exact allowed callback routes, secure HttpOnly cookies where supported by SSR auth flow, session refresh without unsafe user metadata trust, logout/revoke and MFA for owners. Failed logins and public endpoints are throttled.

Saving an editor record includes expected version; 409 preserves the user's form and offers reload/copy, never silently overwrites a concurrent change. Warn on unsaved navigation. Archiving is reversible; delete controls explain references. Destructive data purge and production restore require an explicit owner action and a fresh backup, never a cron running unreviewed destructive SQL.

Receipts and Arabic rich text escape names, order fields and user content. Links use protocol/host allowlists as appropriate. Add CSP with nonce/hash-compatible Next configuration, `frame-ancestors 'none'` on admin, strict `connect-src`/`img-src`/`worker-src` for selected services, no unsafe eval, HSTS after TLS verification and same-origin mutation checks. Reader worker is local, not a CDN script. API error logs use request IDs and redaction. Cron/export backups never expose credentials or raw customer payloads in GitHub artifacts.
